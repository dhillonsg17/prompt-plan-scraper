# Prompt Plan Scraper

A URL + a natural-language request → structured records, without Firecrawl or another scraping service. Node fetch retrieves raw HTML. Playwright handles JavaScript, infinite scroll, virtualized lists and model-identified pagination. Cheerio executes a declarative extraction plan generated by an LLM.

The engine has **no investor, product, domain, URL-path or keyword rules**. The investor example is a saved plan derived from that page's observed DOM; it is not consulted for other URLs or prompts.

## Install and run

Requires Node.js 22 or newer.

```sh
npm ci
npx playwright install chromium
export OPENAI_API_KEY='your-key'
# Optional: select a model supporting Responses API Structured Outputs.
export OPENAI_MODEL='gpt-4o-mini'

npm run scrape -- \
  --url https://startups.gallery/investors \
  --prompt 'Return all investor names in the directory, with fields name and profile_url.' \
  --browser --out investors.json
```

For a different page, change only the URL and request, for example `Return each product's name, displayed price, and product_url`. No schema or selector needs to be written by the caller. Fields must be available in the DOM; computed summaries, inferred facts and multi-page research require a different extraction stage.

Use the cheapest model that passes your site's extraction checks. The default is configurable rather than assuming a particular model is always cheapest or available to your account.

## How it avoids wasting tokens

1. Fetch HTML directly. Opt into browser rendering only when needed; block images, media and fonts.
2. Remove scripts, CSS, SVGs, comments and irrelevant attributes. Preserve selector attributes and semantic structure.
3. Replace repeated sibling groups with a few examples, including the final item. Keep the original page intact for extraction. Do not send every directory entry to the LLM.
4. Ask the LLM **once** for record/field CSS selectors and optional navigation controls, using a strict JSON Schema. Never execute model-generated JavaScript.
5. Validate that plan and extract every observed record in code. Extract on each browser step to retain rows from virtualized lists. Deduplicate exact records, resolve relative URLs and preserve missing fields as `null`.
6. Cache plans by model, prompt, URL, sample and planner version. Identical inputs need zero new API calls; changed inputs replan. Supplied plans also need zero API calls.

`--budget` bounds sample tokens (default 5,000). Oversized samples fail explicitly rather than silently cutting off data. `metrics` reports raw/sample tokens, actual API usage when available, cache status and traversal stop reason. Counts use `cl100k_base` as a consistent comparison estimate; actual model billing can differ. Total API input also includes instructions, request, URL and schema overhead.

On the live investor run, approximately 100,000 raw HTML tokens became approximately 4,700 sample tokens: **about 95% less page input**. The LLM output is a small plan rather than 692 generated records. Browser traversal and extraction use no LLM tokens.

## Prepare or replay without an API key

Inspect the compact representation and exact planning instructions:

```sh
npm run scrape -- --url https://startups.gallery/investors \
  --prompt 'Return all investor names, with fields name and profile_url.' \
  --browser --prepare --out prepared.json
```

Send `instructions` and `input` from that file to any LLM capable of producing the schema in `src/planner.js`; save the returned JSON. This also makes the project usable with a local model by providing its output via `--plan`.

Replay the included demonstration plan without an API key:

```sh
npm run scrape -- --url https://startups.gallery/investors \
  --prompt 'Return all investor names in the directory, with fields name and profile_url.' \
  --browser --plan examples/investors.plan.json --out investors.json
```

The demonstration plan was generated by the assistant from inspected page structure. No live OpenAI API call was made for the included dataset because no API key was configured. The API request, structured-output parsing, usage reporting and cache are covered by contract tests with a mock response; real API credentials/model access still need a live integration check.

## Included results and coverage

- `examples/investors.names.txt`: all names, one per line.
- `examples/investors.result.json`: names, profile URLs, plan and run metrics.
- `examples/investors.verification.json`: independent comparison against the public sitemap.

Collected October 6, 2026: **692 distinct investor profiles**. All 692 matched the site's sitemap; no missing or extra profiles. Names are taken from each card's heading, not reconstructed from slugs. Responsive duplicates are removed.

Browser stability alone cannot prove completeness. Delayed requests, CAPTCHA, inaccessible content, filters or broken pagination can limit extraction. `--max-steps` defaults to 200; hitting the limit or a pagination cycle writes observed results and exits with code 2. Static mode explicitly reports single-HTML coverage. Inspect and regenerate saved plans after layout changes; nonzero matches do not guarantee an old plan still has the intended meaning.

## Implementation and tests

- `src/acquire.js`: bounded raw fetching, browser rendering, scrolling, load-more and next-page traversal.
- `src/dom.js`: compact sampling, token estimates, selector execution and deduplication.
- `src/planner.js`: schema validation, Responses API call and exact-input plan cache.
- `src/cli.js`: command line interface and JSON output.

```sh
npm test
```

Tests cover arbitrary product-style records, Unicode, missing fields, URL resolution, sampling versus full extraction, oversized input, schema errors, API contract/cache/incomplete responses, delayed below-fold content, pagination and traversal bounds. Browser tests need Chromium installed.

Page content is treated as untrusted data in the LLM instructions. API keys are read only from the environment; `.env` and caches are ignored by Git. This is a local CLI for trusted callers. Before turning it into a public URL-fetching service, add host/IP restrictions, isolated browser execution and resource limits suitable for your deployment.

The API integration follows [OpenAI Structured Outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
